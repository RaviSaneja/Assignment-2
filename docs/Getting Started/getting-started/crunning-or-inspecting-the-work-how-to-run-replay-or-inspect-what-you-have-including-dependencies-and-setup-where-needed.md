## **Running or Inspecting the Work**

The Intelligent Clinical Support System (ICSS) is currently available as a visual and interaction-design prototype. The project can be inspected through the 16 interface designs, three illustrated storyboards, system architecture, system flowchart and accompanying design rationale.

### **1. Accessing and inspecting the prototype**

The supplied PNG and JPG files can be opened using a standard image viewer, web browser or design application. The accompanying Word report provides explanations of the design decisions, proposed AI architecture and project limitations.

The following files provide the recommended starting points:

| File                      | Purpose                                                   |
| ------------------------- | --------------------------------------------------------- |
| 4.1 – System Architecture | Understand the overall system structure                   |
| 4.2 – Main Storyboard     | Inspect healthcare-specific use cases                     |
| 4.3 – Storyboard 2        | Examine human–AI interactions                             |
| 4.4 – Storyboard 3        | Review detailed interaction scenarios                     |
| 4.5 – Flowchart           | Follow the overall system workflow                        |
| Interface Designs 1–16    | Inspect individual system components                      |
| Pre-Final Report          | Understand design rationale and implementation boundaries |

### **2. Replaying the patient journey**

The intended patient interaction can be manually replayed by inspecting the interface designs in the following sequence:

1

User role selection

2

Authentication

3

Consent and privacy

4

Symptom entry

5

Patient questionnaire

6

Personalised follow-up questions

7

AI-generated health information summary

8

Success or failure outcome

9

Feedback and user control

Additional interactions can be inspected through the diagnostic centre, chatbot and clinical decision-support interfaces. Insurance and emergency assistance designs demonstrate proposed future extensions.

### **3. Replaying the demonstration scenarios**

| Scenario                  | Inspection method                                           |
| ------------------------- | ----------------------------------------------------------- |
| Women's health assessment | Review questionnaire, follow-up and summary screens         |
| Diagnostic report support | Inspect report upload and clinical review interfaces        |
| Asthma symptom monitoring | Follow the respiratory healthcare storyboard                |
| Failure and recovery      | Inspect failure, retry and success states                   |
| Clinical decision support | Review patient context, AI insights and supporting evidence |
| User feedback             | Inspect correction, feedback and privacy controls           |

### **4. Dependencies and setup**

| Component                      | Requirements                                                     |
| ------------------------------ | ---------------------------------------------------------------- |
| Interface designs              | Standard image viewer or browser                                 |
| Storyboards and flowchart      | PNG-compatible image viewer                                      |
| Design rationale               | Microsoft Word or compatible document reader                     |
| Interactive design prototype   | Original design workspace or shared prototype link, if available |
| Proposed LLM integration       | LLM service or locally hosted model                              |
| Proposed RAG integration       | Embedding model, vector database and healthcare knowledge base   |
| Proposed diagnostic processing | Document extraction and image-processing tools                   |
| Future backend                 | Authentication, secure storage and access-control services       |

No software installation, API credentials or programming environment is required to inspect the supplied static designs.

### **5. Current execution limitations**

The supplied materials demonstrate the intended system interactions but do not include executable source code, dependency configuration, API credentials, installation instructions or a verified interactive prototype link.

Therefore, the current work can be inspected and manually replayed through the visual artefacts. Full execution of the proposed LLM, RAG and diagnostic processing capabilities requires further implementation.
